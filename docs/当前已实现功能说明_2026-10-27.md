# 患者随访系统：当前已实现功能说明

更新日期：2026-10-27。本文按当前代码实现整理，基线提交为 `45654c0`。用于产品交接、试用和界面改版回归核对，不将需求规划或菜单占位视为已经完成。

## 1. 系统定位和主要流程

目前系统围绕患者资料收集、原件保存、医生核对和按就诊日期整理档案工作。核心流程是：医生建立患者 → 生成专属二维码 → 患者阅读须知并提交信息及可选原件 → 医生审核建档申请 → 将原件送入病例识别工作区 → OCR 生成候选 → 人工选择患者、核对字段和就诊日期 → 确认入档 → 在患者工作区按日期查看。

另一条流程是患者通过专属邀请创建账号或用已有账号认领档案，之后登录患者中心提交后续资料，查看本人的资料状态和就诊记录。扫码建档和患者账号认领是两个独立入口，扫码提交基本信息不会自动完成账号认领。

医生还可以创建所属学生账号，配置学生对医生名下患者的查看、录入、审核权限。学生使用医生工作台，由后端按实际身份和当前权限限制可见数据及操作。

## 2. 身份、登录与会话

### 2.1 登录入口

- 登录页面仅提供“患者”“医生团队”“管理员”三个入口。
- 医生团队入口同时接受医生和学生，后端识别数据库中的实际 doctor/student 身份，不需要用户再选择。
- 管理员不能通过医生团队入口登录。身份不匹配、密码错误、停用账号均不能成功登录。
- 账号密码登录成功后记录上次登录时间；失败登录、读取当前身份不会更新该时间。
- 密码输入支持显示或隐藏，身份标签支持键盘切换。
- 登录后按实际角色进入相应工作区；工作区提供退出登录。
- 前端统一处理认证请求和登录失效，路径适配同时支持根路径和反向代理子路径部署。

### 2.2 安全和访问范围

- 密码采用哈希保存，服务端签发并校验访问令牌。
- 后端接口重新检查账号状态与实际角色，不仅依赖前端隐藏按钮。
- 不同医生团队的数据隔离；学生不能通过猜测患者或原件 ID 绕过访问范围。
- 学生或其所属医生停用后，后续请求被拒绝。
- 原件和预览响应禁止缓存；已被用户看到或下载的内容无法追溯收回。

## 3. 管理员工作区

### 3.1 账号列表

- 查看全部账号，并分别进入医生账号、学生账号列表。
- 展示显示名称、登录账号、账号类型、所属医生、启用状态、上次登录和操作。
- 上次登录以北京时间显示，无历史时间显示“暂无记录”。
- 支持按名称或账号搜索、类型筛选、启停状态筛选以及刷新。
- 可启用、停用账号，接口限制不合适的目标操作。

### 3.2 开通账号

- 可创建医生、学生和患者账号。
- 填写登录账号、显示名称、初始密码并确认初始密码。
- 两次密码不一致时前端阻止提交；两个密码输入有独立显示/隐藏按钮。
- 学生必须选择所属的启用医生。
- 患者账号创建后仍需通过医生专属邀请认领患者档案。
- 账号重复或字段不符合规则时返回可读错误；成功后清空密码。
- 服务端记录账号创建和启停事件；当前没有完整统一审计管理页面。

## 4. 医生患者工作区

### 4.1 患者名单和最小建档

- 一级功能侧栏、二级患者名单、右侧患者档案组成工作区。
- 支持按患者姓名或系统编号搜索。
- 新增患者通过弹窗进行，只需医生确认的姓名即可建立最小档案。
- 新建患者归属当前医生，自动生成系统患者编号。
- 选择患者在同一页面切换档案，不展开患者列表行，不跳转新地址。
- 名单和档案区域独立滚动，档案顶部保留选中患者信息和操作按钮。
- 支持刷新选中患者档案；慢请求返回时有保护，避免覆盖后来选中的患者。

### 4.2 患者档案

- 展示患者基本信息、就诊记录、已经确认的结构化病历及关联原件。
- 按医生确认的就诊日期组织资料，同一天多份已入档资料聚合为同一次就诊。
- 尚未入档的建档资料、患者上传资料或病例来源单独列为待整理内容。
- 已入档来源避免重复展示，旧资料没有确认日期时标为日期待确认。
- 从来源资料可以查看原件或进入识别核对流程，具体操作依实际权限提供。
- 档案不会把 OCR 候选或仅暂存的草稿当成已确认的正式记录。

### 4.3 专属建档二维码

- 在选中患者的档案顶部按需打开二维码弹窗。
- 同一有效专属码可重复打开、重印；二维码不会因切换患者列表而自动提前加载。
- 弹窗展示患者姓名、二维码、患者端地址和当前有效状态。
- 可打开患者扫码页面、打印二维码和停用二维码。
- 二维码停用后已有打印码也失效。
- 二维码使用部署配置的外部访问地址，并支持应用子路径。
- 本地和公网数据、令牌相互独立，不能仅替换链接域名混用。

## 5. 手机扫码建档与申请审核

### 5.1 患者扫码页面

- 检查链接是否可用，并区分可填写、等待审核、已通过、被驳回等状态。
- 首先展示当前生效的患者须知标题、版本和全文。
- 患者明确勾选同意后进入填写；系统不把滚动行为当作已阅读或已同意。
- 采集患者姓名、性别、出生日期、本人或家属协助信息。
- 专属码对应医生预设患者姓名；其他基本信息仍须审核。
- 首次提交可选附带 JPG、PNG 或 PDF 原件，文件最大 8 MB。
- 图片提交前可预览；文件选择允许手机系统提供相册、拍照或文件菜单，不强制只启动相机。
- 提交时记录对应须知版本和同意回执。

### 5.2 防重复与补交

- 提交按钮阻止重复点击；服务端对专属链接串行检查并处理幂等重试。
- 专属码存在待审核申请时再次扫码显示等待审核，阻止再建重复申请。
- 已通过后显示建档已通过；须明确选择“补交病历”才能进入补交流程。
- 补交文件重新进入待审核状态。
- 被驳回后允许重新填写提交。
- 历史申请保留，不因本次提交自动删除或合并。
- 通用共享链接的服务端能力仍存在，可供不同提交人使用；当前主要页面引导使用患者专属码。
- 对 HTML 网关错误、请求过大和服务异常提供可读提示，避免直接暴露 JSON 解析错误。

### 5.3 医生审核

- 建档申请列表展示基本信息、提交时间、中文状态和附件是否存在。
- 区分未上传附件和实际文件缺失，未上传时不显示虚假的原件已保存状态或查看按钮。
- 资料操作与审核操作分组，支持查看原件、送入识别、批准、驳回。
- 批准使用绿色动作样式，驳回使用红色危险动作样式。
- 批准后更新或建立对应患者资料，补交资料进入后续整理流程。
- 学生须具有相应患者的查看、录入或审核权限才能执行对应操作。

## 6. 病例上传、OCR 和人工核对

### 6.1 病例缓冲区与原件

- 医生可上传 JPG、PNG、PDF 到病例缓冲区，最大 8 MB；PDF 最多 10 页。
- 医生上传可以先不绑定患者；识别姓名只作为候选，不自动匹配或创建患者。
- 学生上传前必须选择已获得录入权限的患者，原件归属其所属医生。
- 可将建档提交或患者上传的原件导入病例工作区，并避免重复导入同一来源。
- 缓冲区展示病例及处理状态，支持刷新、打开核对、查看原件和审核记录。
- 保留上传原件，并提供受访问控制保护的原件读取和逐页预览。

### 6.2 OCR 能力

- 使用本机 CPU OCR（RapidOCR/ONNX），不需要向外部大模型传送病历。
- 支持图片和多页 PDF，提取原文、页码和位置，供字段证据定位使用。
- 按标签保守提取字段，不推断原文没有记载的诊断或结论。
- 支持候选字段：姓名、性别、年龄、就诊时间、医疗机构、科室、门诊号、报告日期、主诉、现病史、既往史、个人史、过敏史、家族史、中医四诊、生命体征/体格检查、西医诊断、中医诊断、药品处方、中药配方、建议/医嘱、胃镜所见、胃镜诊断、病理部位、病理诊断、幽门螺杆菌、肠上皮化生。
- OCR 日期支持常见日期形式和日期时间连写；缺失或有歧义时要求人工补填，不以上传日期冒充就诊日期。
- OCR 完成后再次检查学生权限，避免识别期间撤权后继续获得结果。

### 6.3 核对工作区

- 原件和字段并排显示，原件按可用空间等比例适配。
- 支持逐页切换和“定位原文”高亮，位置与原件预览坐标对应。
- 右侧字段单独滚动，底部保留患者选择、就诊日期及“暂存”“确认并入档”“驳回”。
- 候选直接预填到输入框，不重复显示候选段落或每个字段的状态选择框。
- 支持修改和补填字段，明确记载“无”时才填写“无”，未知内容保留空白。
- 暂存保存草稿，包括主动清空后的空字符串；刷新后不会恢复被清空的旧候选。
- 有已暂存草稿时禁止重新 OCR 覆盖人工处理内容。
- 暂存不会进入正式患者档案。

### 6.4 统一入档和审核记录

- 确认入档必须人工选定患者并确认就诊日期，还要满足必要的病例内容检查。
- 不根据识别姓名自动绑定患者，已有来源必须归入原患者。
- 统一确认全部非空内容：保持原候选的记为确认，更正、冲突或人工值记为更正，空字段保持待确认。
- 入档后的已确认字段和就诊日期锁定；后续补填空白字段也须再次统一确认才生效。
- 支持驳回及查看病例审核事件历史。
- 病例审核记录与学生授权历史不同：前者仍保留，后者已按产品要求移除。

## 7. 学生账号和当前权限

### 7.1 团队管理

- 医生在“设置 → 学生与权限”查看所属学生列表。
- 列表展示姓名、登录账号、状态、当前权限、上次登录时间和操作。
- “刷新”旁为“新增学生”，新增通过弹窗填写账号、姓名、初始密码和确认密码。
- 密码可独立显示/隐藏，关闭弹窗清空密码，错误在弹窗内显示。
- 医生可启用或停用自己的学生；不能管理其他医生学生。
- 学生自己没有创建患者、生成二维码、管理团队或再授权能力。

### 7.2 权限设置

- 每个学生通过“设置权限”弹窗配置当前权限，没有授权历史按钮或弹窗。
- 新设置作用于所属医生名下全部当前及后续新增患者，不逐患者勾选。
- 查看权限默认勾选，录入和审核独立选择；录入或审核必须同时具备查看。
- 录入包括上传、OCR 和暂存；审核包括确认入档、批准或驳回等对应操作。
- 日期区间在一行设置；“永久有效”勾选后日期置灰并使用空时间边界保存。
- 日期按自然日处理，截止当天仍有效。
- 姓名只显示一次，备注选填并放在末尾。
- 只保留当前权限配置，保存更新同一行，不新增权限历史；并发保存也不会叠加多份配置。
- 关闭查看、到期、未生效或停用都会限制后续请求；前端隐藏和后端校验同时生效。
- 旧逐患者配置不会因迁移自动扩大，需医生明确保存新版全范围设置。
- 旧授权历史接口已移除，已撤销及过期的历史授权已通过迁移清理。
- 按疾病队列授权尚未实现，列在后续任务中。

## 8. 患者账号认领与患者中心

### 8.1 专属邀请认领

- 服务端支持创建、查看状态、撤销专属邀请，使用邀请令牌和 6 位核验码。
- 邀请有有效期、使用状态和错误次数限制；多次核验失败会锁定邀请。
- 患者可创建新账号认领，也可登录已有患者账号认领。
- 新账号由系统分配 8 位数字账号，患者设置并确认密码，完成后显示账号供保存。
- 认领完成后账号与患者档案关联，可进入患者中心。
- 当前医生主要工作区围绕建档二维码操作；邀请生成等接口能力不等同于已有完整独立的邀请管理页面。

### 8.2 患者中心

- 未认领账号显示等待关联和操作指引，可退出登录。
- 已关联后展示本人姓名、系统患者编号、账号关联状态。
- 可阅读当前患者须知全文。
- 通过按钮展开随访资料表单，填写资料发生日期、资料名称、可选说明、附件，并明确同意当前须知。
- 支持取消提交、查看资料时间轴、处理状态和本人的就诊记录。
- 医生确认后的资料才按已确认事件展示，不能自行把候选或待审核资料标记为正式结果。
- 只能访问本人关联档案和原件。

## 9. 服务端、数据与部署能力

- FastAPI 提供页面和接口，SQLAlchemy 管理数据，Alembic 管理结构迁移。
- 数据实体包括账号、患者、就诊、邀请、建档链接与提交、须知版本与同意、患者资料、病例原件与字段、审核事件及学生当前权限。
- 健康接口供本地与部署后检查使用。
- 支持应用根路径或 `/patientfollowup` 等子路径，页面资源、接口、重定向和二维码共同适配。
- Linux 部署使用独立运行用户、systemd 服务、Nginx 反向代理、独立配置和持久数据目录。
- 已有 HTTPS 启用及证书自动续期配置、每日同机数据库和原件备份、版本目录及切换回退方式。
- 数据目录与代码版本分离，更新代码不会重建业务库或覆盖原件。
- 当前公网仍为试用环境；没有配置自动异机备份。
- 公网未启用大模型，OCR 与大模型聊天是分开的能力。代码中的模型接口需显式配置并启用，不属于当前可用的医生智能助手。
- 当前功能分支包含未合并 main 的医生/学生功能，部署必须包含其提交，不能直接用较旧 main 覆盖。

## 11. 界面改版必须保留的回归清单

- 三种登录入口与四种实际角色，账号启停和跨医生隔离。
- 管理员筛选、开通账号、确认密码、所属医生与上次登录显示。
- 患者搜索、弹窗新增、切换不跳页、慢请求保护、按日期聚合和原件去重。
- 专属码打开、重印、停用、患者须知、同意、附件预览、提交和错误提示。
- 待审防重、批准、驳回重提、通过后明确补交、无附件时正确显示。
- 图片/PDF 上传、原件查看、逐页预览、真实 OCR、证据定位。
- 暂存空值持久化、草稿不入档、禁止 OCR 覆盖、人工患者和日期确认、统一入档锁定。
- 学生弹窗新增、关闭清密码、弹窗错误、当前权限同一行更新、永久与自然日边界、实时撤权效果。
- 患者认领注册/登录、核验码、本人资料、后续上传和退出。
- 根路径与部署子路径、手机页面、键盘操作、弹窗滚动和二维码打印。
- 本轮展示调整不得恢复授权历史、增加逐患者权限选择、改动数据模型或删除现有业务记录。
