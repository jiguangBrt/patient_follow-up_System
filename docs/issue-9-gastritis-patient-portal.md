# 慢性胃炎与胃黏膜肠化病情档案

本轮从已上线的 main 创建 `codex/issue-9-gastritis-patient-portal`，将患者扫码建档改为自动归属发码医生，并增加手机首页、个人信息、诊疗记录和专病健康档案。患者建档自动完成不代表临床资料已经核对；患者量表保存为自述，医生或获审核权限的学生确认后生成正式记录。

## 设计依据与实现范围

依据 #9 及其基本信息、症状病史、诊断用药检验子任务，以及仓库中的《杜宏波主任信息随访网站设计构思》。采用文档中的症状分级与既往病史选项。用户本轮关于自动建档、公共二维码和手机组织的要求优先于旧文档的逐人审核流程。

1. 基本信息：姓名、性别、出生日期、手机、身高、体重、民族、职业、文化程度、居住地区；按出生日期计算周岁，BMI 为 kg/m²，展示一位小数。手机填写不等于短信验证。
2. 生活方式：吸烟、支数、年数和戒烟时间；饮酒、频率、每次量、年数和戒酒时间；饮食多选及睡眠。按是否吸烟饮酒显示追问。
3. 基本病情：原文共29项（包括体重下降），逐项保留未知、有、无；有症状可分三级。体重下降追问时间、kg，胃痛追问疼痛性质，食欲问题追问性质，并保留其他症状补充。
4. 既往病史：文档16种疾病多选及补充内容、来源；总体未知、明确无、有独立保存，空的多选不能推断没有病史。
5. 幽门螺杆菌：感染、次数、最近感染时间、治疗和复查结果、来源；明确没有感染时隐藏并排除感染追问。
6. 诊断、治疗用药和关键检验：逐条记录日期、名称、内容与来源，禁止未来日期或缺少来源。系统不推荐治疗，也不把 OCR 候选自动变为正式临床事实。

## 记录版本与确认

`gastritis_records` 每次保存追加新版本，包含记录日期、填写来源、操作者、确认人和确认时间。旧版本不覆盖。复诊可沿用最近版本填写，也可以选择历史版本查看后另存新版本。

医生确认病情记录时，直接依据真实审核权限保存正式新版本并记录确认人和时间，不再要求先确认量表选项与计算口径。患者只能保存自述，不能将自己填写的内容标记为医生已确认。

学生查看、录入和审核权限分别校验。仅有查看的学生没有保存按钮；录入学生只能保存草稿；有审核权限的学生可确认新版本。保存取得写锁后重验登录/导师状态和授权，阻止等待期间已失效的权限继续写入。

患者私密凭据限制到单个患者。公共二维码只提供入组入口，不提供患者列表或其他患者资料；切勿将公共二维码当患者身份凭证。患者 API 无权把自述标成确认。档案响应禁止缓存。

## 入口与人工验收

- 患者：医生公共码或个人码 → 首次进入“我的”填写基本信息 → 自动归属医生；之后首页有“健康档案”“诊疗记录”，底部只保留首页和我的。
- 医生：患者管理 → 选择患者 → 顶部“慢性胃炎病情档案”。原件审核仍在现有病历确认工作区。
- 上传：诊疗记录中添加一次就诊资料，在上传控件下勾选已阅读并同意；须知通过链接展开，不强制每次铺满整个手机页面。

使用虚构资料验收：首次扫码自动建档、刷新和二次扫码识别、两个患者互不泄露；当前量表保存并重新打开，症状与感染史保持未知与无的区分；复诊保存第二版而第一版仍可查看；上传原件可由医生读取；患者自述不能直接确认；学生只读、录入、审核及跨医生隔离分别验证；根路径和 `/patientfollowup` 子路径均检查。

本轮不增加短信服务、咨询、挂号、AI健康问答、医保码或家庭成员选择。实际手机系统文件菜单仍需手机实测。公网部署与运行状态以本轮最终核验记录为准。

## 胃镜与病理功能移除 2026年10月29日

档案界面改为基本病情、既往病史、个人信息、诊疗记录四个分类，一次只显示一组。首次打开基本病情，仅显示可展开的症状入口；切换分类保留未保存输入，查看患者历史版本时分类按钮仍可切换。桌面和390px手机布局及切换后保存已用隔离虚构资料实测。

按用户后续明确要求，移除健康档案中的胃镜与病理整组字段，包括慢性胃炎、胃黏膜肠化、报告日期、医院、胃镜诊断、病理部位、病理诊断和该组来源。API量表不再返回此分类，新提交包含 `gastroscopy` 时拒绝保存，防止旧页面重新写回已移除内容。

迁移 `d62b4c8e901a`（上一版本 `a91c4e8f602b`）直接清理 `gastritis_records.payload` 每个历史版本的顶层 `gastroscopy` 键。只删除该键，不删除整条版本，也不修改记录时间、状态、来源、操作者、其他量表数据、账号、原件或其他业务表。与顶层同名的嵌套字段不属于清理目标。没有该键的记录不重写。

当时量表版本升级为 `gastritis-20261029-v2`。量表口径确认流程随后按用户要求整体移除，见下文。降级只回退迁移版本标记，不伪造已删除的病情值，并明确提示需要迁移前数据库备份才能恢复原值。正常代码回退不能恢复被清理的数据。

新增迁移回归覆盖不同患者、多次历史版本、草稿与确认状态、空值、无目标键及同名嵌套值，逐项验证只有目标键被删除；其他字段及业务表不变、外键完整、再次执行幂等，并验证降级不会编造恢复已删内容。此前2026年10月28日的验收记录描述当时版本，不代表已移除功能仍在当前范围。公网是否已完成本次清理以主任务最终核验为准。


## 量表口径确认功能移除 2026年10月29日

按用户要求，完整删除“量表选项与计算口径确认”功能：页面控件、提交接口、请求模型、响应中的口径确认信息，以及病情正式确认前的口径确认门槛均移除。旧接口 `/doctor/gastritis-options/confirm` 返回404。保留实际临床审核权限校验，医生和有审核权限的学生仍可确认病情记录并记录确认人和时间，患者仍只能保存自述。

迁移 `e73c5d9f012b` 基于 `d62b4c8e901a` 删除 `gastritis_option_confirmations` 表、索引及其全部记录，相关ORM模型也已删除。此清理仅针对退休功能，其他表、病情历史版本、真正临床审核信息、账号和原件保留。降级只建立兼容的空表并明确警告，不能恢复已删除记录；历史值恢复需要迁移前备份。

新增回归覆盖无口径确认前置时医生可直接确认、学生审核权限独立、患者不得确认、旧接口404，以及升级删除目标表和索引后其他所有业务表记录完全不变。降级为空表而不伪造恢复，再次升级与元数据核对均验证。此前的验收记录描述历史实现，不表示退休功能仍在当前产品范围。
