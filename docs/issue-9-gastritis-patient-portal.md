# 慢性胃炎与胃黏膜肠化病情档案

本轮从已上线的 main 创建 `codex/issue-9-gastritis-patient-portal`，将患者扫码建档改为自动归属发码医生，并增加手机首页、个人信息、诊疗记录和专病健康档案。患者建档自动完成不代表临床资料已经核对；患者量表保存为自述，医生或获审核权限的学生确认后生成正式记录。

## 设计依据与实现范围

依据 #9 及其基本信息、胃镜病理、症状病史、诊断用药检验子任务，以及仓库中的《杜宏波主任信息随访网站设计构思》。采用文档中的症状分级与既往病史选项。用户本轮关于自动建档、公共二维码和手机组织的要求优先于旧文档的逐人审核流程。

1. 基本信息：姓名、性别、出生日期、手机、身高、体重、民族、职业、文化程度、居住地区；按出生日期计算周岁，BMI 为 kg/m²，展示一位小数。手机填写不等于短信验证。
2. 生活方式：吸烟、支数、年数和戒烟时间；饮酒、频率、每次量、年数和戒酒时间；饮食多选及睡眠。按是否吸烟饮酒显示追问。
3. 胃镜病理：慢性胃炎与胃黏膜肠化分别记录有、无、未知；报告日期、医院、胃镜诊断、病理部位与诊断、来源。原件统一从诊疗记录上传，填写来源时可引用资料编号。
4. 基本病情：原文共29项（包括体重下降），逐项保留未知、有、无；有症状可分三级。体重下降追问时间、kg，胃痛追问疼痛性质，食欲问题追问性质，并保留其他症状补充。
5. 既往病史：文档16种疾病多选及补充内容、来源；总体未知、明确无、有独立保存，空的多选不能推断没有病史。
6. 幽门螺杆菌：感染、次数、最近感染时间、治疗和复查结果、来源；明确没有感染时隐藏并排除感染追问。
7. 诊断、治疗用药和关键检验：逐条记录日期、名称、内容与来源，禁止未来日期或缺少来源。系统不推荐治疗，也不把 OCR 候选自动变为正式临床事实。

## 记录版本与确认

`gastritis_records` 每次保存追加新版本，包含记录日期、填写来源、操作者、确认人和确认时间。旧版本不覆盖。复诊可沿用最近版本填写，也可以选择历史版本查看后另存新版本。

负责医生通过真实界面确认当前量表版本的选项、三级含义及年龄/BMI计算口径，保存说明和时间。未确认口径时可保存自述或草稿，不能确认正式档案；系统不预填“医生已确认”。医生确认入口展示计算公式与分级，并可展开完整量表逐项核对。该实际操作仍须由医生本人完成，测试中的虚构确认不是客户验收。

学生查看、录入和审核权限分别校验。仅有查看的学生没有保存按钮；录入学生只能保存草稿；有审核权限的学生可确认新版本。学生不能代替负责医生确认量表口径。保存取得写锁后重验登录/导师状态和授权，阻止等待期间已失效的权限继续写入。

患者私密凭据限制到单个患者。公共二维码只提供入组入口，不提供患者列表或其他患者资料；切勿将公共二维码当患者身份凭证。患者 API 无权把自述标成确认。档案响应禁止缓存。

## 入口与人工验收

- 患者：医生公共码或个人码 → 首次进入“我的”填写基本信息 → 自动归属医生；之后首页有“健康档案”“诊疗记录”，底部只保留首页和我的。
- 医生：患者管理 → 选择患者 → 顶部“慢性胃炎病情档案”。原件审核仍在现有病历确认工作区。
- 上传：诊疗记录中添加一次就诊资料，在上传控件下勾选已阅读并同意；须知通过链接展开，不强制每次铺满整个手机页面。

使用虚构资料验收：首次扫码自动建档、刷新和二次扫码识别、两个患者互不泄露；六类量表保存并重新打开，症状保持未知与无，慢性胃炎有且肠化未知/无/有分别展示；复诊保存第二版而第一版仍可查看；上传原件可由医生读取；患者自述不能直接确认；学生只读、录入、审核及跨医生隔离分别验证；根路径和 `/patientfollowup` 子路径均检查。

本轮不增加短信服务、咨询、挂号、AI健康问答、医保码或家庭成员选择。未对真实医生的量表口径确认和实际手机系统文件菜单做自动化替代。公网部署与运行状态以本轮最终核验记录为准。
