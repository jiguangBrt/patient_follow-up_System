## 1. 启动独立验收环境

双击项目根目录的 **本地启动.bat** 即可。脚本会自动准备环境，等服务启动成功后打开统一登录页；如果服务已经运行，则直接打开现有页面。使用期间保留命令窗口，按 Ctrl+C 停止。

也可以在项目根目录运行：

```powershell
uv run python scripts/start_review.py
```

脚本自动迁移专用测试库、准备虚构账号和样例，再启动 `127.0.0.1:8010`。统一登录地址为 `http://127.0.0.1:8010/`，在同一页面选择患者、医生或管理员，三种身份共用同一端口。现有 `.env`、`data/app.db` 和原来的上传目录不受影响。重复运行不会重置账号密码或已有测试记录；端口被占用时，先使用已运行的页面，或加 `--port 8011` 启动。

| 统一登录页 → 管理员 | `aaa001` | `12345678` |
| 统一登录页 → 医生 | `ddd001` | `12345678` |

### 手机开热点、电脑连接热点时

手机可尝试直接访问电脑在热点中的 IPv4 地址。启动脚本默认只允许本机访问；需要手机测试时，另开 PowerShell，指定电脑 WLAN 的 IPv4 地址：

```powershell
uv run python scripts/start_review.py --host <电脑的热点IPv4地址> --port 8011
```

保持窗口运行，在手机浏览器打开 `http://<电脑的热点IPv4地址>:8011/`。热点重连后地址可能变化，应重新查看电脑的 `ipconfig`。此入口沿用同一验收库；停止该命令即可关闭。部分手机热点或 Windows 防火墙会阻止访问，电脑上检查成功并不代表手机一定能连通。

账号仅为本机隔离验收使用。患者账号需认领档案后才能查看本人资料；如果验收环境里已经绑定过，可以在管理员页另建患者测试账号。

首次运行新版脚本时，旧的 `review_admin` / `review_doctor` 会原地改为上述新账号并使用新密码，内部用户 ID、患者归属及审核记录不变。

## 2. 医生端布局

登录统一从首页进入，患者、医生、管理员通过同一张登录卡片的三个选项切换。选错身份时服务端拒绝发放登录令牌；退出及会话失效都返回统一登录页。手机尺寸下收起介绍区，只保留身份选项与登录表单。

电脑端左侧侧栏：

| 栏目 | 当前用途 |

## 3. #8：账号管理与入口复用

### 账号开通、停用及旧会话

2026-10-24 更新：开通账号需两次输入初始密码，两个密码框可独立显示/隐藏；不一致时不能提交。账号列表显示最近一次账号密码成功登录的北京时间；旧账号在更新前没有历史时间，先显示“暂无记录”，下次成功登录后更新。错误密码、选错身份、停用后的失败登录和普通页面刷新均不更新时间。

1. 管理员登录 `/admin`，分别新建医生、患者测试账号。用户名为 3–50 位字母、数字或 `_ . -`，密码至少 8 位。
2. 医生账号登录 `/doctor`，应进入医生工作台；患者账号登录 `/patient`。尚未认领时，应提示通过医生邀请认领。
3. 在另一个标签页保留刚登录的医生/患者页面。管理员停用该账号，列表应立即显示“停用”。
4. 被停用账号重新登录应失败；旧页面刷新或发起读取/提交也应失败，不能靠原令牌继续操作。医生端应回到登录界面。
5. 管理员重新启用后，应能重新登录。医生/患者账号不得访问 `/admin/accounts`，也不得开通管理员。
6. 试用重复用户名、空名称、短密码，应该得到明确错误，并且列表不新增无效账号。

### 专属建档码、重印、停用与后续补交（2026-10-21 更新）

1. 双击根目录的“手机扫码测试.bat”，会读取电脑 WLAN 地址并在 8011 端口启动手机入口。手动启动可用 `uv run python scripts/start_review.py --host <电脑WLAN的IPv4> --port 8011 --public-base-url http://<电脑WLAN的IPv4>:8011`。指定地址保存在忽略的 `.local/issue_8_10_review/public-base-url.txt`，电脑入口重启后也会用它生成二维码。热点重连导致地址变化时，重新启动手机入口，再重启电脑入口。
2. 医生登录后，在“患者管理 → 新增患者”只输入医生确认的姓名，点击“保存并生成建档二维码”。二维码长期可用，不限制扫码次数，也没有 6 位核验码；“打印二维码”打开浏览器打印对话框。
3. 手机扫码，先阅读并同意当前患者须知，再填写性别、生日、操作员。姓名由医生锁定，接口也拒绝改名；病历为选填，可从手机相册或文件中选择 JPG / PNG / PDF，不强制直接打开相机。不上传直接提交应成功。
4. 在患者管理里再次点击“建档二维码 / 重印”，应得到与首次完全相同的链接和二维码；不会新建一个码。申请待审核时，换浏览器或再次扫码应显示“信息已提交，等待医生审核”，无法重复提交；不同提交标识并发请求也只能新增一条申请。批准后扫码显示“建档已通过”，只能选择文件补交 JPG / PNG / PDF；驳回后允许核对并重新提交。补交同样需要等待审核，每次提交记录须知版本及同意时间。
5. 医生点击“停用二维码”，再扫码应提示停用。停用前打开的页面再次提交也应失败；重新进入重印界面仍显示停用状态，不会悄悄恢复。其他医生不能重印、停用或读取该患者资料。
6. 试用不勾选须知、未来生日、篡改姓名、只传一部分文件字段和伪造文件类型，都应拒绝；相同提交重试不会重复生成记录。只提交基本信息也允许医生审核通过；患者专属申请审核会关联原患者，不会另建同名患者。
7. 没有上传文件的申请应显示“仅提交基本信息，未上传病历文件”，不出现原件查看或识别按钮。有文件时可查看和识别；资料操作与审核操作分组留出间距，“批准”为绿色、“驳回”为红色。已有历史申请保留，不自动删除。

患者专属码持有者可读取该码内的基本信息并提交资料，应将纸张只交给对应患者。旧的限时邀请接口保留兼容，但医生工作台不再使用其核验码流程；通用建档入口也改为引导医生先录入姓名。

当前手机测试依赖电脑和热点保持运行。患者拿回家长期使用仍需部署固定公网 HTTPS 地址，并设置 `PUBLIC_BASE_URL=https://<固定域名>` 后重新打印二维码；旧纸张中的本机 IP 无法自动变成公网地址。打印码依赖验收数据库和稳定的 `AUTH_SECRET_KEY`，请保留相关本机数据。

## 4. #10：病例原件、字段缓冲与医生确认

### 缓冲、提取与证据

1. 医生从侧栏进入“病例识别与审核”，上传横拍门诊样例。原件支持 JPG/PNG/PDF，8 MB 以内，PDF 最多 10 页。
2. 上传后应显示“缓冲区 · 未绑定患者”，患者列表不应因识别姓名自动增人或绑定账号。
3. 点击“运行本机 OCR”。候选应包含姓名、性别、年龄、就诊时间、医院、科室、门诊号，以及主诉、现病史、既往史、四诊、生命体征、诊断、处方、建议等独立字段。
4. 点击“定位原文”，预览应定位到对应页并高亮原文。横拍阅读预览会转正；“打开原件”取得的仍是原文件，原件 SHA-256 可追溯。
5. 胃镜样例检查胃镜所见、诊断、取材部位；病理 PDF 检查病理部位、诊断、肠上皮化生、幽门螺杆菌。

### 逐字段审核与入档

1. 打开审核页，滚动右侧字段列表。左侧原件与底部患者选择、三个操作按钮应始终保持原位；在列表滚到底时也不带动整页滚动。
2. 字段只显示名称、预填候选的输入框和原文定位入口，不重复显示候选段落或每项审核状态选择。直接核对并修改姓名、主诉和现病史；未知项留空。
3. 点击“暂存”，重开资料检查修改及清空的输入框均被保留。此时仍不绑定患者，草稿不进入正式档案，也不能重新 OCR 覆盖已暂存内容。
4. 在“确认入档患者”中人工选择已有同名患者，或明确选择按已确认姓名新建。系统不会根据 OCR 名称自动选择患者。
5. 点击“确认并入档”，统一确认所有非空输入值，空白项不入档。需要正确姓名和至少一项病历内容；姓名与所选档案不一致、选择其他医生的患者或未选择归属时应拒绝。
6. 返回“患者管理 → 查看档案 → 结构化病历档案”。只应显示已确认字段，未确认内容不作为医生结论；原件、审核人、时间及历史可追溯。
7. 可以继续填写已入档记录中原来空白的字段；“暂存”只保留草稿，再点“确认并入档”才补入正式记录。已经入档的确认值锁定；更正既有结论需另建更正资料保留来源。底部仅有“暂存”“确认并入档”“驳回”三个按钮。
8. 另上传一份资料，点击“驳回”。原件和历史应保留，但不产生正式病历记录。

### 原入口衔接与异常

- 患者既有上传：患者详情的资料时间轴内，点“提取候选与逐字段审核”，复用原文件；OCR 候选先不绑定。确认入档时只能归回原患者，避免误换归属。
- 通用申请原件：从建档申请点“识别并逐字段审核”。待批准申请可按医生核对后的姓名创建档案，同时关联原申请及同意记录，保留原件；已批准申请只能入原档案。
- 上传 `blank-manual.png` 后运行 OCR，应进入人工处理；没有内容的字段保持空白，不自动填“无”。可以按原件手工录入，再统一确认入档。
- 所有内容均需对照原件人工核对；冲突字段统一确认时记录为人工更正，保留原始候选和证据。不可解析、类型伪装或超限文件应拒绝。
- 两个标签页打开同一资料，先在一个页保存，再在旧页保存，应提示版本冲突，刷新核对后才能继续。
